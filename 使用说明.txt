Release Desk · 版本发布工作台（Go Edition）
接口初始化：记录上线后需要手动调用的接口，维护所属端、HTTP 方法、网关相对路径、无参/必填参数、Query/Body JSON 模板、前置条件和结果核对方式。点击“手动调用”选择测试或线上环境（默认测试），核对地址及参数后每次填写 Authorization Bearer Token，再明确发送。Token 与响应不落盘，不自动重试或跟随跳转，HTTP 状态不能代替业务验收，完成状态由用户维护。三端入口在设置 initialization_base_urls 中集中配置，服务商保留 spapi 前缀。初始化事项参与导出，扫描只记录、不调用。

双击下载的 ReleaseDesk-软件版本.exe 启动；本地构建亦可运行 dist\ReleaseDesk.exe。
界面与资源内嵌 EXE，不需要 Python、Go 或 Node 运行环境。系统需安装 Microsoft Edge WebView2 Runtime。

主要功能
1. 版本总览：读取 SQL 仓库版本目录，按版本号倒序排列，手动加入记录。
   新建版本独立读取设置中的代码仓库，仅列 release- 开头的本地分支及已有远端跟踪分支，去重后按名称倒序，保留搜索和手动输入。SQL 目录候选与导入来源保持不变。
   版本详情可归档；归档后左侧隐藏，在“归档版本”中可查看与恢复，记录和执行历史完整保留。
2. 定时任务：Handler、操作类型、Cron/频率、描述、待办状态、待上线/已上线标记。
   操作类型支持新增、修改、关闭；历史删除记录仍保留。关闭表示本次发版需停用调度，不等于已关闭或已发布，也不会从软件自动调用调度系统。表格、详情、编辑、AI 扫描及导出共用现有 action 字段，发布状态独立维护。
3. 配置：文件名、前缀、完整内容、是否必须配置、描述、待上线/已上线标记。
4. SQL：独立表格，解析真实 SQL 正文分类，先创建表、再修改表、最后初始化数据，同类型按数字顺序。
   不根据目录或文件名分类；混合文件按最高优先级展示，内部语句保持作者原顺序。
5. Topic：名称、变更类型、分区数、消费组、描述。
6. 变更与验证：修改内容、服务、验证方式、日志检索条件、预期和实际结果。
7. 双击表格单元格复制完整原文；配置可一键复制；修改项可复制完整 AI 验证提示词。
   鼠标悬停单元格显示完整内容浮层，保留换行，长内容可直接在浮层内滚动查看。
8. AI 模板：保留本地填写协议与示例供 Codex 技能使用，侧栏不再显示模板按钮。
9. 版本文件：每 2 秒扫描合法 JSON。AI 增量更新不会删除省略项或撤销人工状态。
10. AI 智能验证：选中修改项及北京时间证据窗口，让本机 Codex 结合对应版本代码与必要的生产证据，自主分析修复目的是否达成。服务、步骤、关键词、预期结果均为可选线索，不按固定日志词或预填步骤机械判定。
    使用已有登录态，只读调用；可能消耗账号额度。区分通过、失败、证据不足、未发现异常与需手动验证；中立状态不计为通过。人工项排在末尾且不允许加入自动验证队列。

设置分类与 AI 接入
“连接与设置”按数据库、日志、代码与 AI、接口调用切换。默认数据库页；切换保留编辑内容，最后统一保存，取消不保存。
数据库页分别填写测试和 UAT 的主机、端口、账号、密码；密码不回填，留空保留已有密码。
日志页填写火山 TLS 的地域、Endpoint、AK/SK；三套环境默认沿用团队当前项目与后端服务日志 Topic，不再配置个人技能目录。
AK 和 SK 都使用当前 Windows 用户加密保存，页面不回填；已有密钥留空保留。密文损坏时可明确重填整对密钥修复，覆盖前保留原密文备份。
“读取项目”只取得元数据。“测试连接”逐环境核对网络、鉴权、Topic 所属项目和读取权限；只查询最近一分钟最多一条，不返回或保存样本，零命中不等于没有读取权限。
网络允许域名和 Topic ID 放在折叠高级设置中。改用其他 Endpoint 时先保存精确主机范围；查询不跟随跳转，不自动扩大联网范围。
代码与 AI 页管理代码仓库、SQL 仓库、Git 作者，提供版本文件夹和“AI 一键接入”。
点击接入后复制指令给本机 AI；助手按当前数据目录生成的 AI接入指引.txt 核对非敏感设置并增量写入六类记录，不复制凭据、不执行 SQL、接口或生产查询。
接入指引不自动修改设置。外部 AI 更新 settings.json 后需用户重启软件读取，不能强制结束运行中的任务。
接口调用页维护测试/线上三端基础地址；Bearer Token 仍在每次调用时临时填写，不保存在设置中。
扫描、日志查询和环境路由三份技能直接内嵌 EXE；软件内调用使用当前构建规则，不依赖个人技能目录。
启动及生成接入材料时刷新 AI模板\skills 下的软件管理副本，并写入当前软件版本与摘要；升级 EXE 后规则一起更新，不覆盖用户的 .codex\skills。
Go 日志客户端随 EXE 分发，已配置直连时优先使用内置入口，未配置时可发现实际可用 MCP。密钥不交给模型、命令参数或提示词。
生产验证固定生产项目与 prod_后端服务日志，软件把用户确认的北京时间起止值转成毫秒，放入短期加密访问范围。模型只提供检索条件与采样量，不能换环境、Topic 或扩大窗口；结束或取消后撤销访问文件。
输出区分真实命中总量、样本数与完成状态，递归脱敏并限制体积，不另存原始生产日志。没有可用数据源时如实记录配置缺口，不伪装取证成功。

Git 与 SQL 刷新
“同步 Git”只 fetch 当前分支上游，不 pull、不切分支，保留本地未提交内容。
“从 Git 导入”列出当前分支中配置作者（默认 huohuo）最近涉及的 SQL 文件。
读取作者提交时的完整内容，不依赖工作区文件是否被删除。
SQL 页“刷新 SQL”同步远端后检查已绑定脚本。新的作者提交会更新未手改的内容。
软件内手工改过的脚本提示冲突；新文件仍需主动导入。
SQL 变化后，旧执行历史保留，新内容重新显示为未执行；执行期间不刷新内容。

测试 / UAT 环境执行
点击一键执行，先查看完整目标列表与 SQL，再确认执行。
默认规则：租户 newlink、newlink+数字、newlink_share 开头；服务商 sp、sp+数字；平台 newlink_pf。
模板库包含在范围内，view、points 等其他库不会被默认规则选中。
所有目标从开始即可见，逐库显示等待、执行中、成功、失败及详细原因。
单库业务失败继续其他库；纯数据 SQL 已成功的库默认跳过，可只重试失败库。
结构 SQL 在执行前读取真实表、字段和索引；已存在对象免除重复 ADD/CREATE，定义仍需完整比较。
执行后再次核验类型、长度/精度、可空、默认值、注释、自动增长及索引列/顺序/唯一性等。
旧成功库含结构语句时仅复核实际结构，不重复执行 INSERT、UPDATE 等数据语句。
结构不同显示“结构不一致”；元数据无法读取或扩展语法无法完整理解显示“待核验”。
支持常规 CREATE TABLE、ALTER ADD/MODIFY/CHANGE/DROP 字段、ADD/DROP 索引及 CREATE INDEX。
支持 ADD/MODIFY/CHANGE 中的 FIRST/AFTER，读取 ORDINAL_POSITION 核对最终位置；连续同锚点插入、多个 FIRST 和重命名按作者顺序归并。位置不一致会定位到具体字段，缺少原始前驱的复杂重排保留待核验。外键、生成列、分区等扩展仍需人工核对。
结构不一致或前序结构未完成核验时，停止当前库的后续数据语句，其他库继续处理。
MySQL DDL 可能隐式提交，失败前的 DDL 不保证回滚；网络或提交结果不确定时标为已中断。
CREATE TEMPORARY TABLE 属于会话内初始化，排序在依赖的持久表/字段变更之后，保留文件内部顺序与跨库限制；不将临时表当成永久表核验，历史只读检查不重放会话数据。
数据库目标与执行结果按名称前缀后的数字升序，例如 sp、sp1、sp2、sp10；租户库同理。

数据与凭据
默认目录：当前 Windows 用户的 %APPDATA%\ReleaseDesk。
版本文件在“版本文件”，历史在 execution-history.json，配置在 settings.json。
任务中心的完整历史在“任务历史”目录，扫描、单项/批量验证和单条/批量 SQL 各有独立任务 ID。
软件重启后可查看已完成结果；异常退出的未完成任务标为“已中断”，不自动重跑。
手工备份按钮导出版本与 SQL 审计；迁移全部记录时请连同“任务历史”目录整体保留。
连接密码在 connection.json 中经 Windows DPAPI 加密，仅当前用户可解密。
数据库密码不包含在版本文件、AI 提示词、示例、导出清单或备份中。
“连接与设置”可分类调整仓库路径、Git 作者、日志连接及密钥、网络范围、测试/UAT 数据库与初始化接口基础地址。
设置中的 scope_rules 可修改匹配规则；建议先使用默认规则并核对执行预览。

通用示例
公开包仅附带 examples\template.json，不包含真实业务版本、SQL 或历史验收资料；学习材料不会自动导入版本列表。

AI 扫描与界面
新建版本可勾选“保存后让 AI 扫描此版本”，已有版本可点击“AI 扫描”。
复用已登录 Codex 和软件内置扫描技能，按设置作者只读扫描代码与 Git。启动前解析所选版本 release-<版本名> 的本地引用并固定 SHA；找不到精确目标就停止，不回退 HEAD 或其他工作分支，不切分支、不 fetch/pull。
候选经协议校验和 SQL 作者原文核对后，备份并增量保存；人工状态和历史独立保留。
“连接与设置”中可打开版本文件夹和数据目录，侧栏保留常用入口。
主题可选深灰蓝、石墨灰、暗夜紫、森林绿、柔和浅色；选择随应用重启保留。
侧栏、主工作区和选中项一起切换色系，通过不同深浅保留导航层次。
长版本备注收在“版本说明”中，页头只保留简短摘要，原始说明不会删除。
配置详情包含描述与“是否必须配置”。可选择“必须配置”“可选配置”或“待确认”；旧记录默认待确认，已有代码默认值且满足本次上线行为时可设为可选，并在描述中记录默认值及依据。该属性不改变上线状态。表格悬停可查看全文，双击复制该项完整内容。
定时任务频率仅保存 Cron，例如 0 0 10 * * ?；列表显示为 0 0 10 * * ?（每天 10:00），双击只复制表达式，悬停查看完整解释。编辑输入框旁实时解释，支持标准 5 段和 Quartz 6/7 段（包含秒及可选年份）；数字星期按对应格式解释。解析失败时提示修正，实际 Cron 未确认可留空并在描述注明。旧记录混在频率中的文字会移入描述保留；解释组件随 EXE 分发，离线使用。
版本设置中将版本状态选为“已发布”并保存后，左侧会将其收进“已发布版本”分组。每次打开软件默认折叠，可点击展开；本次打开期间保留用户展开选择。归档版本仍只从归档列表进入。
顶部主题、备份、恢复及版本操作按钮可悬停查看用途说明。AI 扫描需确认目标版本、额度与写入影响后启动；新建版本勾选扫描也会先确认。归档与恢复版本均显示确认弹窗，取消或关闭不执行该操作。
SQL 详情增加“仅核验结构”：先确认环境、服务器和全部目标库，再用只读事务查询表、字段、索引及字段顺序，不执行 DDL 或数据语句。可安全复核旧的待核验和已中断目标；只读结果独立记录为结构核验，不代表初始化数据已经执行。
SQL 页面可选择测试或 UAT，每次启动默认测试环境，UAT 需手动切换。两套连接在设置中分别填写，使用当前 Windows 用户加密保存；测试沿用 connection.json，UAT 使用独立 connection-uat.json，未配置时不回退另一环境。状态与历史按环境和服务器独立显示，旧无环境记录属于测试。单项、失败重试和批量执行均先预览环境、服务器和全部目标库，连接或脚本改变后需重新预览；只需勾选确认，不要求输入“执行”。
SQL 与“变更与验证”表格支持逐项勾选、全选和取消全选，切换版本或表格会清空选择。
SQL 批量执行先预览全部脚本与逐库范围，勾选确认后按 SQL 正文类型排序：建表、改表、初始化数据。
每条 SQL 独立展示所有目标库的结果；单库业务失败继续后续库和脚本，审计保存异常则停止。
版本扫描与 SQL 预览、单条和批量执行可以同时进行，进度及停止操作彼此独立；同一时间仍只允许一个扫描和一个 SQL 批次。扫描更新了尚未执行的预览正文时，必须重新预览确认，不会自动改用新内容执行。
变更与验证每行的“更新代码”只更新这一项的代码说明、提交来源和验证条件，只读本地 Git 引用（release-<版本名> 及已有远端跟踪引用）；本地引用需自行通过 Git 工具同步。软件读取时不拉取远程、不切换分支、不覆盖工作区，不查询生产或执行 SQL。保留旧验证历史，条件变化后旧结论失效；手动项也可重新评估。任务复用扫描进度及独立停止入口。
发布对比以实际已发布旧版与当前版本最终代码为准，上次扫描或同版本未上线的中间提交只是开发线索。旧版没有该项新需求时按从无到有验证最终目标；原本已上线的功能仍比较其真实旧行为。发布基线无法确认时说明待确认，不猜成空，也不将同版开发修错伪装为线上 bug。
批量验证使用统一证据时间范围，最多同时运行 6 项 Codex 验证，有空位立即补充等待项，每项独立保存结论；缺少预填服务、关键词或预期结果也会交由 AI 分析，单项失败或证据不足不影响其他项。停止批次同时取消所有运行项，不再启动等待项；已保存结果保留，取消后的迟到结论不写入。保存异常停止整批后续取证，避免无法可靠留档时继续消耗额度。
批量验证弹窗可选择 1～6 的并发数，首次默认 6，成功提交批次后记住本次选择；重启仍沿用，实际同时运行数不超过勾选项数。后端校验范围，不能通过直接请求突破上限。
生成变更记录时，修改内容说明原问题、修复机制和关键边界，预期结果写业务目标与反例，验证方式提供可选路径和风险场景，日志关键词仅作真实源码线索；不能把某句日志写成唯一成功条件。个人扫描技能与软件内扫描遵循相同规则。
AI 验证提示词包含代码仓库、SQL 仓库、作者及事项来源，并排除旧验证结果。AI 先集合目标版本代码与生产日志，再自主判断是否达到业务目标；参考条件可按实际证据调整，未命中关键词可改用相关检索路径，无法取得日志时明确尝试和原因。结果分别保存验证目标、代码判断、日志发现和综合理由，单项、批次展开及任务中心均可回看和复制；旧历史不补造分析。没有专属成功日志可使用其他可靠证据；本地代码存在或零错误本身不代表上线已生效。标题、代码来源或其他判断输入变化后，旧结论失效，历史仍保留。
两类批次均可收起进度面板、最小化到托盘继续，也可点击停止批次；已完成结果独立保留。
桌面模式使用整机单实例锁：重复运行切回已有窗口，不打开第二个窗口。
点击 － 收进右下角系统托盘，后台继续工作；点击托盘图标或再次运行 EXE 恢复。
点击 × 直接退出并取消后台任务，限时保存审计后释放单实例锁，不再留下无窗口进程。
托盘图标右键提供“打开主窗口”和“退出软件”；退出与点击 × 共用保存和取消流程。
退出时 SQL 已提交的 DDL 无法撤回，未确认结果记录为“已中断”，不自动当作失败重试。

开发与工程结构
internal/update/：GitHub 正式版检查、版本比较和可信下载链接；来源集中在 source.json，不读取业务记录或凭据。
cmd/releasedesk/：唯一可执行入口与 Windows 链接资源。
internal/app/：启动生命周期、本机 HTTP 接口和依赖装配；业务回归测试集中验证跨包协作。
internal/ai/：版本扫描、单项与批量 AI 自主验证、CLI 适配及提示词协议。
internal/sql/：测试及 UAT 独立连接、范围预览、逐库执行和脚本队列；script/ 解析 SQL，schema/ 核验真实结构。
internal/initialization/：手动初始化请求、参数与目标快照校验；Token 和响应不落盘，不自动重试或跳转。
internal/logquery/：内置 TLS 客户端、日志连接 DPAPI 加密、团队默认后端 Topic、限时只读访问与脱敏采样。
internal/git/：版本候选、作者过滤导入和刷新冲突保护；repository/ 封装 Git 命令及配置锁。
internal/release/：版本与事项增删改、归档恢复及人工发布状态。
internal/settings/：本机环境设置与主题偏好更新。
internal/storage/workspace/：共享状态、版本协议、文件监听、增量合并及正式逐库审计。
internal/storage/fileio/：原子文件替换与 JSON 落盘。
internal/tasks/：统一任务目录与独立结果持久化；taskcenter/ 提供历史查询和精确停止接口。
internal/platform/：desktop/ 窗口托盘、目录与剪贴板；process/ 子进程树；secrets/ Windows DPAPI。
internal/versioninfo/：软件更新记录与构建信息；versioning/ 业务版本排序；policy/ 有单位的执行上限。
internal/identity/：随机标识和内容摘要。
web/：内嵌前端入口；scripts 放脚本，styles 放样式，prompts 放 AI 模板与 Schema。
build/windows/：图标与 Windows manifest 原始资源。
examples/：示例版本 JSON，不自动导入真实数据目录。
tools/：commentcheck 注释检查；qa 隔离界面回归；packagecheck 核对实际公开压缩包边界。
.work/：检查产物、隔离测试数据和整理前源码备份，统一收纳，不进入安装包。
dist/：EXE、使用说明、示例与 ZIP 包。
.tools/、node_modules/：开发依赖，EXE 运行不需要这些目录。

构建：运行 build.ps1，默认并行测试、静态检查和注释检查，再生成 dist\ReleaseDesk.exe。
普通构建及 -ArchiveOnly 构建成功后，均自动复制 ReleaseDesk-软件版本.exe 到当前用户桌面的 dist 文件夹，并校验文件一致性；同版本覆盖更新，不影响其他版本。同步失败会报错，完整构建仍保留在项目 dist\releases 中。
本机私有 Go 工具链在 .tools\go，不修改系统 PATH。
GitHub 发布：先更新软件版本记录，完成本地测试和打包，再提交并推送代码以及对应 vX.Y.Z 标签；GitHub Actions 在 Windows 上自动测试、打包并发布 EXE、ZIP、SHA256SUMS.txt。普通代码推送不直接发版。CI 显式使用 -SkipDesktopCopy；本机构建默认仍同步桌面 dist。
软件更新：桌面启动后后台检查正式版，每 6 小时复查；点击顶部“检查更新”可手动查看。网络异常不影响本机操作，不上传业务清单或读取凭据。只有完整的对应版本 Windows EXE 可用才显示下载新版按钮；下载后先关闭旧版，再运行新版，本机数据目录继续使用原记录。

任务中心
左侧“任务中心”统一查看版本扫描、AI 验证和 SQL 执行，可按任务类型筛选。
运行中可查看进度并停止；停止后保留已完成结果、逐库状态和对应验证条件与证据。
停止绑定本轮任务 ID，旧弹窗不会误停新的任务；收起面板或最小化到托盘会继续后台工作。
回看结果只读本机记录，不重新执行 SQL，不重新调用 Codex。

软件自身版本记录
左下角点击“v版本号 · 更新记录”，可查看软件版本、构建编号、时间、源码摘要和历史功能。
早期功能补录到 1.0.0；当前版本与本次变更以界面和软件版本记录为准，不用业务 5.x 版本给软件编号。
记录源：internal\versioninfo\releases.json；与工作台管理的业务 5.x 发布版本互不影响。
版本规则：主版本为不兼容变更，次版本为新功能，补丁版本为问题修复。
每次构建归档到 dist\releases\软件版本\构建编号，保留 EXE、安装包、source.zip、构建记录及 SHA256SUMS.txt。
构建期间若其他会话修改源码则拒绝发布，以保证源码快照、校验值和 EXE 对应。
源码已建立 Git 提交及正式发布标签。历史补录不补造构建日期或校验值，每次新构建独立归档。

退役 SQL：名称含明确的【已退役，勿执行】标记或 data.lifecycle 为“已退役”时，列表禁选、全选跳过，详情保留复制和执行明细，不再提供执行、重试及新核验。预览后退役同样会使旧执行令牌失效；AI 刷新和 Git 再导入不会重新启用。
