# 内置环境路由规则

- 每次取数前明确测试、UAT 或生产；以当前连接配置与工具声明、资源实际名称为依据，不通过网址外观或服务名独自判断。
- TLS 可以覆盖多个环境：先列项目，按测试、UAT、生产项目选择，再核对主题的服务归属。历史项目 ID 只是线索，不能在不同电脑或账号间盲用。
- Bamboo 默认连接中，MySQL、Redis、Nacos、dbviz 属于测试；SkyWalking、Grafana、ES 属于生产；TLS 与 RDS 需要按项目或实例明确选择。默认接线不是永久事实，实际连接声明不一致时必须先澄清。
- 使用测试数据库或测试 Nacos 查到的字段、配置、路由，不能据此声称生产已部署或具有相同运行值。
- 生产业务明细没有授权连接时，不擅自用测试数据替代。可以利用已授权的生产日志或可观测性证据，仍无法确认则说明缺口。
- 用户没有给出环境且无法从本轮明确授权推导时先询问；指定了环境就保持，不在连接失败后自动切换。
- 环境、查询窗口、代码快照和部署依据都应写入本轮证据说明。提交时间、版本记录发布日期和 HTTP 成功不单独证明部署事实。
- 所有取证只读，不执行 SQL 写入、修改配置、调用初始化接口或触发调度，不通过制造样本来提高验证通过率。
