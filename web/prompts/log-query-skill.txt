# 内置日志查询与代码复核

先遵循同包环境路由规则，明确目标环境、用户确认的起止时间和业务事项。代码来源、实际部署、运行样本分别判断，提交时间不代表部署时间。

## 工具与连接

- 本轮提供软件内置 TLS 查询命令时，必须优先使用该命令。入口已固定生产项目、prod_后端服务日志 Topic 和用户确认的时间窗；只接受 action/query/limit，不自行换环境、Topic 或时间参数。可以执行 describe 查看真实资源和固定窗口，不读取加密访问文件正文。
- 没有内置查询入口时，发现当前会话实际提供的日志 MCP，按真实环境资源使用工具；没有工具不等于服务故障，应提示在软件“连接与设置 → 日志”填写只读 AK/SK。不要寻找个人技能目录或另一台电脑的查询脚本。
- 规则、Go 查询入口与团队后端日志映射随软件内置，不携带访问密钥或登录态。没有可用数据源时明确说明取证尚未配置，不把缺少授权报成业务没有日志。
- 不为了查询修改用户的全局 Codex 配置、安装插件或扩大网络允许域名。只调用本轮已配置且被只读访问策略允许的主机。
- 凭据仅由软件查询进程或已授权 MCP 在内存中使用；不要把密钥放进提示词、命令参数、源码、版本文件、响应摘要或交付材料，不读取 connection*.json、log-connection*.json 或 log-access*.json 的正文。

## 查询与判定

1. 固定用户确认的环境和时间窗，不自动扩大范围或用当前时间替代历史复测时间。
2. 核对工具真实支持的查询参数；毫秒时间必须按接口约定传递，不能把忽略参数后的默认窗口当作指定窗口。
3. 结合目标版本、实际发布基线和最终有效代码，先定位核心入口、关键业务分支、异常及上下游关联线索。
4. 区分查询失败、零命中、只有入口样本、关键结果样本及明确反证。不以没有错误日志、本地代码存在或 HTTP 200 单独宣告发版通过。
5. 返回上限只是采样上限，不把采样条数当作全部命中数。混合线程或邻接日志须核对服务、路径、业务标识和堆栈归属，避免拼接无关证据。
6. 对新业务关注关键流程与结果；对已上线 bug 比较实际发布前后的机制和线上样本，不把同版本未上线的开发中间态当作旧版。
7. 有充分代码与运行信号相互印证、且没有核心反证时可高概率确认，并说明推断和未覆盖范围。实际查询成功但不足以确认时可中立记录“未发现异常”；鉴权或网络失败不能使用此结论。
8. 静态代码无法通过现有日志观察关键结果时，指出人工验证步骤，不能通过主动执行接口、SQL 或业务任务制造样本。

只输出必要的脱敏证据与结论。不要输出客户正文、手机号、密码、Token 或整份工具原始响应；不要把未核验信息改写成生产事实。
