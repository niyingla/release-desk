Release Desk · AI 接入与自动填写指引

适用范围：配置本机软件的非敏感设置，并将有来源证据的版本发布记录写入软件。生成这份指引不会自动修改设置、扫描代码或执行业务。

一、接入软件设置

1. 先读取本指引与现有 settings.json。下方设置快照只代表当前保存值，初始示例路径不代表另一台电脑一定存在。
2. 在本机发现实际代码、SQL Git 仓库及提交作者，核对路径、当前分支与相关提交。没有足够信息时只询问缺失的作者或目录，不能凭路径名称编造仓库，也不 fetch、pull、切分支、提交或推送。
3. 可填写的非敏感字段：code_repository、sql_repository、git_author、verification_concurrency、verification_log_domains、initialization_base_urls、scope_rules。仓库使用绝对路径，作者不能为空；并发范围为 1～6。
4. 扫描技能、日志查询规则、Go 只读查询入口与环境路由随软件内置，不配置个人技能目录。日志页预填团队生产、测试、UAT 的项目及各自后端服务日志 Topic；AK/SK 由用户在软件中填写并加密保存，AI 接入不得读取或复制。没有直连授权或可用 MCP 时说明缺口，不伪造查询成功。
5. 初始化接口环境入口与数据库范围规则只按用户已经确认的实际环境修改，不能把测试配置当作生产事实，也不自行扩大允许联网的主机范围。
6. 修改设置前读取并备份原文件，保留未知字段，仅合并经过核对的字段。先写同目录临时文件并解析校验，替换前检查原文件没有被其他操作修改，再原子替换。
7. 外部 AI 写入设置后提醒用户重新打开软件，使内存中的仓库和设置快照更新；不要强制退出正在运行的程序或打断任务。版本记录由软件文件监听读取。

二、自动填写版本发布记录

1. 先读取软件内置扫描技能和文件协议，确认本次目标版本、作者、真实 Git 快照及实际已发布基线。用户未指定版本时从当前发布分支确认，不能把模板示例号或 Maven 日期版本当作本次版本。
2. 记录六类事项：job（定时任务）、config（配置）、sql、topic、init_api（上线后接口初始化）、verify（变更与验证）。没有有效变化的类型可以为空，不为凑表格制造记录。
3. 配置事项依据代码中的读取与默认值判断 required，区分必须配置、可选配置和待确认；必要说明写 description，配置内容本身保持合法原文。
4. SQL 读取所选作者提交中的完整原文和来源信息，不生成、改写或执行业务脚本。分类依据 SQL 正文，保留混合脚本内部顺序；会话临时表属于数据初始化中间态，不能抢在持久字段变更前执行。
5. 初始化事项必须核对实际方法、参数、服务内路径 service_path 和含服务前缀的网关路径 url。只知道服务内路径时保留已知内容并标明映射待确认，不能猜路径。扫描不调用接口、不读取或保存 Token。
6. verify 仅记录核心业务目标、新业务关键流程和实际 bug。现有日志无法观察关键结果时声明手动验证并给出人工步骤；生成阶段不查询生产、不把代码存在或历史结论当作本轮通过。
7. 从现有版本 JSON 增量合并，复用稳定 ID，保留省略的旧项、归档标记、人工状态、执行审计和验证历史。上次扫描和同版本未上线的中间实现不能自动成为线上旧版。
8. 保存前备份并校验完整 JSON，使用同目录临时文件和原子替换；有并发变更时先重新核对。不要操作软件内存或内部审计文件。
9. 完成后报告实际写入路径、修改的设置键、六类数量、代码来源、未确认信息及是否需要重新启动软件，不声称已经执行 SQL、部署或完成线上验收。

三、凭据与执行边界

不要读取、复制或修改 connection*.json、log-connection*.json、log-access*.json、登录凭据、密钥文件、执行历史及任务结果。不要把数据库密码、火山密钥、Token 或客户正文写入指引、提示词、版本记录或源码。
数据库连接由用户通过软件设置页单独填写并加密；接口 Token 每次临时输入。AI 接入只配置非敏感设置和版本内容，不自动执行 SQL、调用初始化接口、查询生产、触发任务、发送消息、发布或推送。
